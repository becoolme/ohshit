1Password 11 月 25 日披露确认，攻击者利用员工的企业 GitHub 账户获取私有源码，并向后端服务推送恶意代码，复制部分客户的管理记录。攻击者还访问了包含基础设施秘密的 CI/CD 系统。员工账户如何失陷、完整攻击时间线、受影响人数及进入生产环境的完整技术链路均未公布。这是已确认的后端入侵，评为 L4；报告不能证明保险库被窃或客户应用发布版本被植入恶意代码。

被复制记录包括姓名及登录邮箱，账户／用户标识，账户创建及最后登录时间，公钥，Secure Remote Password（SRP）参数，某些邀请、账户供应及恢复邮件链接中的令牌，以及版本和文件数字标识等内部账户元数据。尚无公开受影响用户总数。1Password 表示，公钥及 SRP 参数不能单独用于访问账户。社区经理解释，SRP 验证值由账户密码与 Secret Key 共同派生，没有公司不保存的 Secret Key，就不能借此猜测账户密码。这些是厂商的解释，不是独立取证结论。

邮件链接令牌的范围不同于保险库保护密钥或账户恢复密钥。账户供应邀请涉及 SCIM Bridge 或 Hosted Provisioning；厂商称已逐一通知处于相关邀请／恢复状态的少量用户。链接令牌还必须配合 SSO 登录或邮件验证码，不能单独打开账户。作为预防措施，公司将六位数字验证码改为十位字母数字混合码，并称内部没有发现利用已暴露供应令牌接管账户的证据。披露未说明所有账户元数据受影响者都已收到个别通知，也未说明全部客户链接令牌均已撤销。

1Password 报告，已停用受影响 GitHub 账户、撤销一个被盗令牌、移除攻击者创建的访问、恢复干净服务版本，并轮换或撤销可能暴露的内部凭据。博客摘要称已触发轮换，已完成操作列表则称已轮换或撤销。公司还报告加强 GitHub、CI/CD 及终端控制，并新增检测覆盖，但没有公开详细配置。不能将这些服务商内部处置转化为要求所有客户轮换全部已保存密码。

公司称保险库、库内条目及其保护密钥、账户恢复密钥、应用和浏览器扩展均未受影响，服务正常运行。员工另行表示，没有证据显示加密保险库被访问或下载。**11 月 26 日 05:11 UTC**，社区经理称，独立专家对更广泛范围及控制措施的核验仍在进行。聘请外部专家不等于独立审计已完成，也不能证明事件最终关闭。来源没有提供 CVE、该活动专用恶意指标、已确认客户账户接管数量或客户端补丁门槛。即使保险库内容仍受保护，账户资料也可能让冒充更具可信度。
