Java4Shell 位于 JVM 用于 Base64 解码的优化机器码中。非法填充可在 Java 拒绝输入之前破坏相邻堆对象。Calif 通过针对应用构造的利用链演示了内存泄露和远程代码执行。主流运行时受到影响且已有公开复现，因此评为 L3；已阅读的来源没有确认真实受害者遭到攻击。

暴露需要受影响的 intrinsic 在支持 AVX-512 VBMI 的 x86-64 硬件上运行，且攻击者输入可进入该路径。Calif 将 OpenJDK 问题追溯到 17.0.6 及之后的受影响构建。Oracle 另行列出 Java SE 8u511b33-perf、17.0.21.0.3、21.0.13.0.3、25.0.5.0.3、27.0.1.0.3，GraalVM for JDK 17.0.21.0.3、21.0.13.0.3，以及 GraalVM Enterprise Edition 21.3.20.0.3。Java 8 PERF 在列，不代表所有普通 OpenJDK 8 构建都受影响。OpenJDK 的逐 CVE 矩阵没有为此漏洞标记 8 或 11。

Calif 在 Keycloak、Jira、Confluence、Artifactory、Jenkins 和 PingFederate 中演示了认证前 RCE，在 Kafka Broker、Solr、Elasticsearch、Gerrit 和 Spinnaker 中演示了认证后 RCE。这些是研究人员测试的应用路径，不能证明每个部署都可被攻破。Calif 还描述了客户端 TLS 路径，因此并非始终需要对外提供入站服务。不存在通用载荷，针对具体产品的武器化利用链仍未公开。

即使应用没有单独公告，也应安装运行时厂商补丁。表格仅覆盖已核实的 Oracle Java SE 发布，未覆盖全部发行版或 GraalVM 产品。在安装正确的厂商构建之前，禁用受影响的 intrinsic 并重启 JVM。上述日志保留与凭据处置步骤属于通用事件响应建议，不是已确认攻击活动公布的入侵指标。

Google 的 11 月 17 日公告说明，对指定托管运行时临时屏蔽 AVX-512 VBMI 至 11 月 30 日，不能泛化为所有 Google Cloud 应用均受保护。自动运行时补丁分发与临时保护的部署范围不同，VM/容器隔离不受影响。Apigee X 的目标是 11 月 18 日 07:00 PST 前完成多数实例、当日 23:59 PST 前完成全部实例；这些是预期，不是完成确认。配置维护窗口的实例缓解后可能保持原版本号。Hybrid 1.17.4 宣布于 11 月 18 日提供，指南描述其自动禁用 intrinsic，不能据此认定已安装修复 JDK。宣告恢复前应核实版本可用性和实际部署。Apigee Edge Public Cloud 没有受影响的客户可见组件；范围内的内部组件仍在打补丁，目标为 12 月 12 日。Hosted Targets、Edge Micro Gateway、Integrated Portals 和 Google Cloud API Gateway 被排除。

Cloudflare 在 11 月 18 日发布六项默认仅记录的托管检测规则；需要检查命中并主动设为阻断。Cloudforce One 同日报告同一 IP 的 ARTEX 与 Java4Shell 活动。这是相关流量观测，不能仅据共同 IP 推断完整攻击链或成功入侵；本文不据此宣称受害者已失陷。

Solace 单独注明产品更新仍待完成。其 11月18日通知列出 AKS 上的 C-EMA/MCA 及清单中的其他产品。Schema Registry 1.1.5 是 11月24日的目标版本，尚不能确认修复已发布。PubSub+ Monitor 未给出发布日期。通用 JVM 缓解不能证明托管 Solace 部署已经完成。
