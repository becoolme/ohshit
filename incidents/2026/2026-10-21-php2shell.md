Two bugs in PHP's own engine, not in some framework or plugin. **Nearly every PHP release back to 5.4 is
affected** by at least one of them. Apache `mod_php` is the highest-risk setup, but PHP-FPM, `php-cgi`,
FrankenPHP and LiteSpeed are all in scope.

The disclosure was planned for October 22. On the evening of October 20 a proof-of-concept video from
Calif, one of the reporting teams, went public by accident, and PHP pushed its releases out on October 21
at 14:00 UTC. So for once, defenders and attackers started the race at the same time.

**Earlier reporting:** Patchstack's partners and watchTowr saw real attack
attempts within hours. Cloudflare saw early attempts too. Sophos had no reports of exploitation, and
nobody had confirmed a successful break-in at the time of writing. We grade by the worst credible case:
public PoC + default configuration + basically the whole web = **L5**.

### Common misreading

Turning off `session.upload_progress` is **not** a fix. It only cuts the confirmed path to
CVE-2026-109619. The out-of-memory bug, CVE-2026-109618, does not need it.

**Update, October 22:** AWS now reports broad exploitation and retrospectively identifies a MadPot attempt on October 17, before public disclosure. The previous disputed status is superseded by this first-hand report. AWS does not establish that the earlier attempts succeeded against real systems. Investigate from at least October 17; the L5 assessment remains unchanged.

**Update, October 23:** Sophos’s October 22 correction supersedes its 16:18 UTC claim of a successful customer compromise. Its 21:21 UTC update says the attempts failed and the Potassium payload was blocked. This revises Sophos’s observed outcome, not AWS’s separate MadPot report. Observed exploit activity remains confirmed and the assessment stays L5, without asserting successful customer infection. Correlate indicators with process, request and file evidence before drawing that conclusion.

**ClearPass, October 22:** HPE confirms these same two CVEs in ClearPass Policy Manager. Versions 6.14.0 / 6.11.15 and earlier are fully affected; 6.14.1 / 6.11.16 provide only partial mitigation, requiring authenticated cluster-admin privileges for the remaining attack. **October 23 correction:** HPE revision 2 released complete hotfixes for 6.14.1 and 6.11.16. Install the matching PHP hotfix in addition to the base release. Restrict CLI and web management to a dedicated segment and firewall policy, and remove public guest portals until patched. The PHP runtime version table and checker above do not assess ClearPass appliance remediation.

PHP also published a separate, narrowly configured upload-progress RCE warning on October 23: [CVE-2026-115560](/incidents/php-session-upload-progress/). It is not covered by the October 21 runtime fixes.

**Tenable, October 23:** TNS-2026-30 and TNS-2026-31 cover these same two PHP CVEs. Security Center 6.9.1 and earlier and Enclave Security 1.9.1 and earlier are affected. Apply the product-specific SC-202610.2 patch: packages cover Security Center 6.6.0 / 6.7.2 / 6.8.0 / 6.9.1 and Enclave Security 1.7.0 / 1.8.0 / 1.9.1, updating embedded PHP to 8.2.35. Updating a separate system PHP does not patch a bundled copy. The runtime checker above covers PHP itself; it cannot verify installation of these appliance patches. No additional exploited-customer count is established.

Standalone patch packages target Oracle Linux 8+ or RHEL 8+. For Enclave, the supported pairings are Security Center 6.7.5 on Enclave 1.7.0, Security Center 6.8.0 on Enclave 1.8.0, and Security Center 6.9.1 on Enclave 1.9.1. Follow the matching standalone or in-pod installation instructions.
