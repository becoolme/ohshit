Hex 于 **2026 年 11 月 24 日** 披露事件。攻击发生在前一天：**69 次恶意请求** 抵达仓库，攻击者在 **六台 Web 服务器** 上执行命令。评为 **L4**，因为软件仓库已遭实际入侵，服务端凭据和账户数据处于可被读取的范围内。目前没有证据证明恶意包已被分发，也不能据此声称 Elixir 应用发生全网入侵。

存在缺陷的是 **hexpm 服务端**，并非每个用户的 Hex 客户端都有命令执行漏洞。其 Erlang term 请求体解析器在所有路由的认证之前运行。仅拒绝函数和新 atom 不足以保证安全：映射可通过 `__struct__` 指定一个已存在的 Elixir 模块。随后错误报告检查这个值，经 Ecto 和 DBConnection 的协议分派触达攻击者指定的回调。命令以 BEAM 进程的操作系统权限运行，不自动等于宿主机 root。

托管服务在 11 月 23 日完成修复。自托管运营者需要部署解码器补丁：受影响源码范围从 `ab1bbcef7cc8395d1056d3b1aa6a174353492d59` 开始，到 `379b0a29bcc95164249f38ad7d772a37a8ff9533` 之前结束。服务端日期和源码提交范围与 Hex 客户端版本号是两回事。补丁递归拒绝 struct 映射；相关库的加固和注册表签名系统更换属于官方报告说明的其他工作。

**已确认什么，还有什么不清楚：** Hex 把数据库每一行与攻击前快照进行比对，并核对了发现的变更。攻击期间的全部 **23 次包发布** 均能对应审计记录；18:00 之后写入的 **62 个包文件** 和 **186 个注册表文件** 与数据库校验值或内容相符。未发现异常包修改或持续访问。这些检查不能证明没有数据被读取，数据库比对也无法发现所有被撤销或被后续正常修改覆盖的变更。文档归档没有已保存的校验值可供同样比对。

数据库读取、环境变量读取和 shell 命令没有日志。可能被读取的账户数据包括邮箱、密码哈希、API 密钥哈希、2FA 密钥、会话及审计日志。从已被攻破服务器发起的私有包读取，可能看起来与合法服务流量一致；直接从存储读取私有文档的行为也没有日志。没有已核实的账户数据被盗总数、签名密钥被盗证据或可列出的投毒包版本。

Hex 已替换基础设施凭据及会话、访问令牌签名密钥，用户因此需要重新登录。**注册表签名密钥是另一把密钥，在报告中仍属尚未轮换的例外。** 维护者正在准备新签名系统，预计随后几天发布相应客户端。应使用官方仓库并跟进发行公告；状态页显示正常，或安装一个此前已有的客户端版本，都不能证明轮换已经完成。

账户用户应修改已有 Hex 密码、更换已启用的 2FA 并保存新恢复码，再重新认证客户端。GitHub 注册用户仍需完成后两项。仅下载公开包的匿名用户没有账户需要重置，但仍应遵循仓库及客户端更新建议。Hex 不要求仅因强随机 API 密钥的哈希可能泄露就统一更换所有 API 密钥；密钥原值暴露或出现可疑使用，则是应吊销密钥的另一个理由。
