Kernel 的 11 月 4 日通知描述两起相连的入侵。被盗 Kernel API 密钥先被用于访问内部档案资料，随后用于进入日志服务商的员工登录身份。被下载的日志含少量 Kernel API 密钥及应用部署中的第三方凭据。攻击者之后通过被盗托管服务账户凭据访问四台 GPU 服务器，其中三台承载客户浏览器会话，另一台是不含客户资料的开发服务器。通知没有解释最初密钥如何被获取，也未确立每个浏览器会话或存储凭据都遭复制。

Kernel 称已吊销被盗凭据、切断日志服务访问、拦截相关 IP、下线服务器、轮换这些服务器可访问的凭据，并通知受影响组织。厂商给出的影响比例为 **0.28% 的客户**，没有绝对人数。客户管理的第三方凭据及会话访问仍须逐组织核查；厂商遏制措施不能证明下游凭据从未被滥用。

公司判断这是逐利挖矿活动，并认为攻击者用 ARTEX 统筹操作。这是厂商分析，不是独立攻击者归因，也不能证明与另一起 [WorkOS 事件](/zh/incidents/workos-internal-gtm/) 属于同一次入侵。浏览器服务已确认凭据暴露及基础设施遭访问，因此评为 L3；厂商报告的客户占比有限，具体范围仍有未解问题。没有公开客户软件补丁或统一安全版本。
