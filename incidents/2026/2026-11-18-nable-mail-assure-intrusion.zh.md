N-able 的公开状态记录修正了先前的运行故障解释：Mail Assure 和 SpamExperts 托管云环境中一台服务器遭到未授权访问。厂商表示，这与 [N-central 事件](/zh/incidents/ncentral-hf2-attack-chains/) 无关。11 月 18 日确认安全事件，与此前的服务中断及状态记录中 11 月 17 日的开始时间不同。

11 月 18 日 03:05 UTC，N-able 表示当时尚无证据显示客户数据（包括租户邮箱）被攻破。这是调查在特定时间点的声明，并非证明没有暴露。后续更新仍在调查。11 月 22 日 CVE 标识了一项漏洞，但已阅读的一手来源未确定初始入口、受害数量、凭据暴露清单或最终数据影响。

20:18 UTC 的更新说明，入站和出站邮件及过滤始终运行。当时管理门户、API、隔离区和日志仍停用，团队正验证安全恢复。较早更新还将邮箱同步列为恢复中的配套服务。这些可用性说明不能证明租户邮箱已遭入侵。

N-able 表示，已向合作伙伴发送针对各自环境、说明是否需要操作的邮件。未收到通信的合作伙伴应联系技术支持。公开转载的一封邮件描述了更具体的凭据操作，但本文尚未通过可读的厂商原始通信核实这些细节，应直接获取自身指引。托管邮件服务商确认遭未授权访问，支持定为 L4；下游影响范围仍在调查。

11 月 19 日 00:01 UTC，N-able 报告已开始测试部分修复措施，其余仍在推进。管理界面、隔离区、日志、邮箱同步及 API 恢复前，都必须通过受控环境中的安全验证。邮件收发和过滤继续正常运行，门户和 API 在测试期间仍停用。这是处置进展，不是服务恢复公告或最终影响结论。

11 月 19 日 04:01 UTC，N-able 表示在修复测试之外继续加强平台安全并调查事件。邮件过滤正常，门户及 API 仍关闭；该更新没有宣布恢复服务或给出最终影响评估。

11 月 20 日 17:45 UTC，N-able 表示修复及安全验证取得进展，正准备恢复服务。门户及 API 在开始恢复前仍停用，邮件收发与过滤继续正常。这是恢复准备阶段的进展，不代表配套服务已恢复或调查结束。

11 月 21 日 23:44 UTC，N-able 宣布管理界面及 API 已恢复，并将事件转入监控。厂商表示服务分阶段恢复，计划进行约一小时的主动稳定性监测，并承诺进一步向客户说明。该更新没有明确确认隔离区、日志、邮箱同步均已恢复，也未给出最终数据影响评估。上文较早的停用描述对应各自日期，不代表当前管理界面及 API 仍停用。


N-able 于 11 月 22 日 14:30 EST 更新称，已修复识别出的漏洞，修复后未发现初始托管服务器以外的利用证据。独立 DFIR 团队正参与调查，厂商承诺两周内提供更完整的根因分析。这是有时间和范围边界的厂商结论，不能当作最终排除影响。公告将管理界面/API 恢复时间取整为 11 月 21 日 23:45 UTC，而状态 JSON 的公告时间为 23:44:43 UTC；两者指同一次恢复，不是两次故障。

厂商 CNA 记录描述了配置中继时使用的 LDAP 同步连接检查。20261121.1943 之前的构建允许已认证 API 用户探测任意内网主机和端口，并向内部服务发送构造流量。CVSS 4.0 评分为 9.3，向量要求高权限；这不能单独证明未认证访问、代码执行或邮箱数据被盗。托管云入侵结论与软件构建边界的范围不同，Local Cloud 运营者应向支持核实适用性及实际补丁交付。

CISA 于 11 月 23 日将 CVE-2026-134624 加入 KEV，独立确认该漏洞曾遭利用，但未证明它是单台托管服务器的初始入侵入口。11 月 26 日期限及取证分诊要求适用于受约束的联邦机构，并非客户恢复完成日期。
