A routine-looking security release with a few nasty pieces. The headline item is an **out-of-bounds write
in the Brotli decoder** (CVE-2026-111497). Anything that decompresses untrusted Brotli data, such as HTTP
bodies, uploads or proxied responses, should treat this as a remote code execution risk.

Two separate bugs (CVE-2026-105483 and CVE-2026-106069) let unusual IP spellings pass **TLS hostname
verification**. That is the check that makes sure the certificate actually belongs to the server you meant
to reach.

The same release ships a `ca-cert` update that **rejects TLS chains containing the compromised eMudhra keys**.
See the [eMudhra incident](/incidents/emudhra-ca/). Already-resumed TLS sessions are not re-checked, so
restart services after upgrading.

We grade it **L4**: a core runtime has a remotely reachable memory bug, and CISA now confirms exploitation of the underlying Brotli CVE. CISA does not identify which downstream products were attacked.

**Update, October 23:** Imperva’s October 22 demonstration reaches RCE through fetched responses and configured request parsers on an official Linux arm64 build. This is laboratory evidence, not a confirmed attack. Other architectures and release lines were not validated by that demonstration. The fixed versions and L4 assessment remain unchanged.

**Update, October 24 — the same Brotli flaw beyond Node.js:** These products embed the vulnerable decoder too. Exposure still requires decoding attacker-controlled data. Python HTTP clients can enable Brotli automatically when an optional decoder is installed; Envoy and Istio require configured Brotli decompression. The Node checker above covers only Node.js, not these separate packages.

cdxgen's advisory covers scanning an untrusted repository that points to an external podspec, and unauthenticated Brotli request decoding at `/sbom` in server mode. Its 12.8.8 binaries still bundled Node.js 24.18.0 despite the intended fix. npm installs use the host runtime instead. Updating host Node alone cannot fix a bundled executable or image. This expands affected-product guidance, not the demonstrated exploit scope: Imperva's lab result remains limited to its tested Node build, and these downstream advisories themselves do not establish real-world exploitation; CISA later confirmed exploitation of the Brotli CVE as noted below.

**Update, October 25 — Go and .NET:** The Go port `github.com/andybalholm/brotli` fixed the same invalid-block-switch logic in commit `33c2a98` on October 23; tag `v1.2.7` contains it. The upstream reporter suggests Go bounds checks may turn the issue into a panic, but did not reproduce that outcome. The Node.js RCE demonstration does not establish Go RCE. Inventory dependencies and decoder reachability, then update and rebuild affected binaries. A framework depending on the library only to encode responses is not evidence of vulnerable request decoding.

Microsoft's October 25 update fixes Brotli in .NET **8.0.33 / 9.0.22 / 10.0.14 / 11 RC3**. Microsoft describes possible memory disclosure/corruption, denial of service or privilege elevation, not a demonstrated .NET RCE. Restart apps using a shared runtime; rebuild self-contained apps and containers, which retain their bundled runtime. These downstream additions do not independently establish exploitation of Go or .NET, and do not change the Node-only version checker.
