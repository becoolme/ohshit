- title: 更换 Chainstack 密码及其他服务的复用密码
  hint: 直接打开已知控制台，在 Settings > Personal > Security > Change password 更换密码，并更换其他服务中复用的密码。无法登录时使用官方账户恢复流程；SSO 登录由身份提供方管理员处理。

  hint: 组织 Admin 或 Editor 打开节点，依次选择 Rotate credentials > Generate new credentials。按实际使用情况，将应用中的 HTTPS/WSS URL、用户名和密码、gRPC x-token 换成新值并测试，然后选择 Complete rotation 和 Deactivate old credentials。完成最后一步前，旧凭据没有失效时限，仍可使用。存在多套活跃凭据时须逐套轮换；此操作不会更改 multichain auth token。

Chainstack 在 11 月 3 日报告中称，攻击者通过未具名的第三方组件进入系统，并访问了客户账户资料库。组织名称、账户持有人姓名、组织成员邮箱及密码哈希可能暴露。由于存放节点凭据的系统可被访问，公司将节点凭据视为已暴露，但未发现凭据已被读取的证据。通知所有客户不代表每位客户的记录均被复制。报告未提供受害者数量或已确认的钱包损失。

厂商称，客户节点、控制台及 API 均未被修改，面向客户的服务持续运行；完整银行卡号及安全码未暴露，因为公司不存储这些资料。这些是厂商调查结论，并非独立取证核实。报告认为事件属于更广泛的 AI 辅助攻击活动，但未说明组件、攻击者或利用编号；与其他具名事件的关联尚未核实。

L4 依据是已确认的生产基础设施入侵及客户账户资料访问，并非已证实的大规模受害人数。客户没有软件补丁可安装。密码、节点凭据及平台 API 密钥须分别处置；只生成新节点凭据，旧凭据会持续有效，直到轮换完成。
