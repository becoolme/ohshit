看着像一次例行安全更新，里面却夹着几个狠角色。头号问题是 **Brotli 解码器的越界写入**（CVE-2026-111497）。凡是会解压不可信 Brotli 数据的地方，比如 HTTP 请求体、上传文件或代理转发的响应，都应该按远程代码执行风险来对待。

另有两个互不相干的漏洞（CVE-2026-105483 和 CVE-2026-106069）能让一些不寻常的 IP 写法通过 **TLS 主机名校验**。这项校验的作用，就是确认证书确实属于你要连的那台服务器。

同一批发版还带了一个 `ca-cert` 更新，**会拒绝包含已失陷 eMudhra 密钥的 TLS 证书链**，详见 [eMudhra 事件](/zh/incidents/emudhra-ca/)。已经恢复的 TLS 会话不会重新校验，所以升级后要重启服务。

我们定为 **L4**：这是核心运行时，有一个能远程触达的内存漏洞，但目前还没有在野利用。

**10月23日更新：** Imperva 在 10月22日的演示中，通过获取的响应及已配置的请求解析器，在官方 Linux arm64 构建上实现 RCE。这是实验室证据，不是确认的攻击。演示没有验证其他架构或版本线。修复版本和 L4 评级不变。

**10月24日更新——Node.js 之外的同一 Brotli 漏洞：** 下列产品也内置了受影响的解码器。暴露仍需要解码攻击者可控的数据。Python HTTP 客户端在安装可选解码器后可能自动启用 Brotli；Envoy 和 Istio 需要配置 Brotli 解压。上方 Node 检查器仅覆盖 Node.js，不能检查这些独立的软件包。

| 产品 | 修复方式 |
| --- | --- |
| Google Brotli C 库 | 按对应版本线升级至 1.0.10 / 1.1.1 / 1.2.1 |
| Bun | 1.4.4 |
| Python Brotli / brotlicffi | 1.2.1 / 1.2.1.0；检查锁文件及已安装环境 |
| Envoy | 1.40.0 / 1.39.3 / 1.38.6 / 1.37.8 / 1.36.12 |
| Istio | 1.31.2 / 1.30.6 / 1.29.9；1.29.9 是 1.29 最后版本，应规划迁移 |
| cdxgen 独立二进制及镜像 | 12.8.9 / 13.5.0；核实内置运行时，不能只检查宿主 Node |
| Debian 13（trixie）brotli 包 | 1.1.0-2+deb13u1；发行版移植补丁使用不同版本号 |

cdxgen 公告涉及扫描指向外部 podspec 的不可信仓库，以及服务器模式下 `/sbom` 在认证前解码 Brotli 请求体。12.8.8 二进制原本计划修复，却仍内置 Node.js 24.18.0。npm 安装使用宿主运行时。仅升级宿主 Node 不能修复内置运行时的可执行文件或镜像。本次扩大的是受影响产品指引，并未扩大已演示的利用范围：Imperva 的实验室结果仍限于测试过的 Node 构建，这些下游公告也未证实真实攻击。

**10月25日更新——Go 和 .NET：** Go 移植库 `github.com/andybalholm/brotli` 在 10月23日通过提交 `33c2a98` 修复同一无效块切换逻辑，标签 `v1.2.7` 包含该修复。上游报告者推测 Go 的边界检查可能将影响限制为 panic，但并未复现这一结果。Node.js 的 RCE 演示不能证明 Go 也能 RCE。应清点依赖和解码可达性，然后更新并重建受影响二进制。框架仅依赖该库编码响应，并不能证明请求解码存在暴露。

Microsoft 在 10月25日通过 .NET **8.0.33 / 9.0.22 / 10.0.14 / 11 RC3** 修复 Brotli。暴露需要通过请求解压、HttpClient 响应解压或 Brotli API 处理恶意输入，前两项默认关闭；.NET Framework 不受影响。Microsoft 描述的可能影响为内存泄露或破坏、拒绝服务及权限提升，并未演示 .NET RCE。依赖共享运行时的应用须重启，自包含应用及容器须重建，因为其中仍保留内置运行时。这些补充没有证实在野利用，也不会改变仅适用于 Node 的版本检查器。
