2026年10月14日，nginx 发布了 **1.30.6（稳定版）** 和 **1.31.7（主线版）**，包含五个安全修复。F5 同一天发布了对应的安全公告和 CVE 记录。漏洞都出在 worker 进程里，控制面不受波及。默认编译加默认配置不会中招：每个漏洞都要求开启某个特定功能，或者以某种特定方式开启。

## 严重程度，各说各的

nginx.org 把**五个都定为“中危”**。F5 的 CVE 记录则给其中三个打了 **CVSS 3.1 8.1**（CVSS 4.0 9.2）：alias/rewrite 溢出、变量计算溢出和 AIO/SSI 释放后重用。高分来自代码执行的可能性。F5 表示，只有在 ASLR 被关闭或可被绕过时才做得到；否则结果就是 worker 崩溃后重启。攻击复杂度被评为高，因为攻击者没法决定服务器怎么配置。有些新闻摘要因为 CVSS 4.0 的 9.2 分把它们称作“严重”，但厂商自己的定级是中危。

## 哪些配置受影响

- **CVE-2026-15176**：location 里用了 `alias`，加上 `rewrite`，再加上在 `set`、`return` 或日志格式里用到 `$request_filename`。这个漏洞能追溯到 0.1.29，所以很老的部署也跑不掉。
- **CVE-2026-93479**：带正则捕获的 `map`，且捕获变量被用在 `root` 或日志格式中。在 1.30.0 / 1.31.2 引入。F5 建议改用命名捕获作为临时缓解措施。
- **CVE-2026-95101**：只影响 HTTP/3。源码编译默认不带 HTTP/3 模块，而且还需要一个 `listen ... quic` 监听，但很多打包好的版本都带了它。
- **CVE-2026-97629**：用了 `ssl_session_cache shared:...` 却没配 `ssl_session_ticket_key` 文件，这是很常见的配置（票据默认开启）。伪造不是每次都能成功，但能绕过客户端证书校验，如果你靠 mTLS 做认证，这一点就很关键。
- **CVE-2026-97205**：`aio`（默认关闭）加上使用 `include virtual` 的 SSI 页面。nginx.org 列出的受影响版本可追溯到 0.8.11；F5 的 CVE 记录只列出了 1.30.0 及之后的版本。开源版的版本范围我们以 nginx.org 为准。

更早那个 HTTP/3 堆溢出（CVE-2026-90439，9月15日在 1.30.5 / 1.31.6 修复）是另一次单独发版。如果你当时跳过了，这次升级会一并补上。

## NGINX Plus 及其他 F5 产品

F5 列出的受影响版本是 NGINX Plus R33 到 R36 以及 37.x，并为 37.0 和 37.1 两条线提供了热修复。五个 CVE 记录里的热修复版本号并不完全一致，所以 Plus 该升到哪个版本，请以 F5 的 K 文章为准，别照抄本页。

加拿大网络安全中心对 F5 10月14日这批公告的汇总里，还列出了 5.7.0 之前的 NGINX Ingress Controller、2.8.0 之前的 NGINX Gateway Fabric、2.24.0 之前的 NGINX Instance Manager，以及 F5 WAF / DoS for NGINX。这批公告还包括同日发布的两个 njs 修复（njs 1.0.2），所以汇总里没说清这些产品分别受五个 nginx CVE 中的哪几个影响。如果你是通过这些产品在 Kubernetes 里跑 nginx，要升级的是产品本身，而不只是你以为它在用的那个镜像 tag。

## 等级

我们定为 **L3**。nginx 挡在相当大一部分网站前面，其中三个漏洞是远程攻击者够得着的内存破坏。之所以没定得更高，是因为每个漏洞都需要非默认或特定的配置，厂商定级为中危，代码执行得先过 ASLR 这一关，而且既没有公开 PoC，也没有利用报告。
