Java4Shell is a flaw in the JVM's optimized machine code for Base64 decoding. Invalid padding can corrupt neighboring heap objects before Java rejects the input. Calif demonstrated memory disclosure and remote code execution through application-specific exploitation chains. A mainstream runtime and a public reproduction support L3; the reviewed sources do not confirm attacks against real victims.

Exposure requires the affected intrinsic to run on x86-64 hardware supporting AVX-512 VBMI and attacker input to reach that path. Calif traces the OpenJDK issue to 17.0.6 and later affected builds. Oracle separately names Java SE 8u511b33-perf, 17.0.21.0.3, 21.0.13.0.3, 25.0.5.0.3 and 27.0.1.0.3; GraalVM for JDK 17.0.21.0.3 and 21.0.13.0.3; and GraalVM Enterprise Edition 21.3.20.0.3. The Java 8 PERF listing does not mean all ordinary OpenJDK 8 builds are affected. OpenJDK's per-CVE matrix does not mark 8 or 11 for this flaw.

Calif demonstrated pre-authentication RCE in Keycloak, Jira, Confluence, Artifactory, Jenkins and PingFederate, and authenticated RCE in Kafka Broker, Solr, Elasticsearch, Gerrit and Spinnaker. These are researcher-tested application paths, not evidence that every installation can be compromised. Calif also describes a client-side TLS path, so an inbound service is not always required. There is no universal payload, and product-specific weaponized chains remain private.

Apply the runtime supplier's patch even when an application has no separate advisory. The table covers verified Oracle Java SE releases, not every distribution or GraalVM product. Until the correct supplier build is installed, disable the affected intrinsic and restart the JVM. Treat the log-preservation and credential-response steps above as general incident-response guidance, not published indicators of a confirmed campaign.

Google’s original November 17 safeguards covered only the specified managed runtimes. Its November 20 update confirms patched Java images and Buildpacks packages; image availability still requires automatic runtime delivery or a customer rebuild and redeployment, as applicable. The temporary hardware mask through November 30 retains its narrower scope; VM/container isolation is unaffected. Dataflow’s November 20 bulletin requires existing streaming jobs to be replaced or restarted and distinguishes standard-container mitigation, patched non-Portable images and pending Portable/Flex images. Managed Airflow’s November 20 releases and environment-variable procedure are separate from Apigee’s rules. Google added links to both detailed procedures on November 23.

Google’s November 18 Apigee update confirms all X maintenance-window customers were updated while retaining 1-18-0-apigee-6, and nearly all ordinary instances reached -10. Earlier advice to check Maintenance Operation logs was incorrect: Google says this mitigation produces none. Hybrid 1.17.4 is now confirmed released with a patched JDK, superseding the earlier availability target; customers still need to upgrade their own environments. Apigee Edge Public Cloud has no affected customer-facing components; its in-scope internal components retain a December 12 patch target. Hosted Targets, Edge Micro Gateway, Integrated Portals and Google Cloud API Gateway are excluded.

Cloudflare released six managed detections on November 18 with Log as their default action; review and explicitly enable blocking where appropriate. Cloudforce One separately reported ARTEX and Java4Shell activity from one IP that day. Shared-source traffic does not by itself establish a chained attack or successful victim compromise, so this observation is not treated as confirmation of compromised victims.

Solace’s November 20 notice confirmed the AKS C-EMA update. Its November 23 revision also confirms the MCA rollout on November 20, superseding the earlier target. Schema Registry 1.1.5 is a November 24 target, not a verified fixed release. PubSub+ Monitor has no stated release date. The two AKS agent updates do not establish completion for the remaining Solace products.

GreyNoise’s November 20 20:18 UTC snapshot documents 261 shaped requests from seven IPs, with no confirmed successful intrusion on its gridpoints. The broader 14-address candidate list includes other tagged scanning activity. The November 24 21:18 UTC refresh retains those shaped-request totals but lists ten broader infrastructure candidates, including three absent from the earlier list. Neither snapshot establishes attacker attribution or successful customer compromise.
