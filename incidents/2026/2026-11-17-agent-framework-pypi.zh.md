遭篡改的是已发布的 Python 元包。微软 11 月 25 日声明明确，仓库代码、其他 Agent Framework Python 包、.NET 包及 Semantic Kernel 未受影响。研究人员在两个官方 PyPI wheel 中发现恶意程序，微软维护者确认将其移除。已证实的恶意分发支持评为 L4。目前仍没有经过核实的受影响安装量或被盗凭据总数。

安装后的 .pth 文件会在所在环境正常启动 Python 时执行导入语句。无需导入 Agent Framework，启动 pip 也可能触发收集程序。彼此独立的虚拟环境不会仅因使用相同 Python 可执行文件而自动感染。载荷读取可访问的环境变量、凭据文件和其他进程的环境，尝试获取 Azure 托管身份及 Azure DevOps 令牌；1.26.2 还发出 GitHub Actions OIDC 请求。这些请求需要对应身份、权限或令牌请求变量，安装包本身不会赋予任意云访问权限。静态收集代码不能证明某台主机成功取得令牌、访问云资源或完成外传。脱离父进程的子进程可能在任务结束后继续运行，具体取决于运行器与容器清理。

疑似发布权限失陷仍在调查中。StepSecurity 较早的文字报告了新建维护者账户；修订后的正文表示，现有证据无法确定具体账户、凭据、初始入口或上传者身份，但同页较早的流程摘要仍保留账户说法。该身份说法尚未核实，Upwind 也未确定具体凭据路径。不能据此推断微软更广泛失陷，或确定攻击者身份。Endor 最初的报告仍称 1.26.2 为最新版，但后续微软确认和当前 PyPI 元数据证明两个恶意版本均已移除。下架不会清理已安装环境，单凭下架当时也不能确定发布权限已完成处置。后来核阅的 PyPI Security 公告记录了与微软共同审查账户并完成处置，但未明确最初的凭据路径。

下表完整列出已公布的恶意 SHA-256 指标。干净的 1.26.0 初始化文件与恶意 1.26.2 恢复后的初始化文件哈希相同，不能仅凭该文件正常就排除环境受影响。

**11 月 19 日跟进：** Wiz 在 11 月 18 日的更新中判断，微软 Engineering System Release Pipeline（ESRP）的客户端证书及私钥疑似失陷。报告称来自 AWS 的发布尝试被拒，随后来自微软持有的 IP 地址空间的尝试成功；这些位置均不能确定攻击者身份。最初如何窃取凭据，以及微软是否确认这一判断，仍未明确。Wiz 对 50 条已采集请求的单一来源分析，将其分为 4 条攻击者侧请求、29 条疑似沙箱/扫描/测试请求，以及对应三起受害者外传的 17 条请求。这不是经独立核实或完整的受害者总数：采集受到限制，后续请求可能被拒收。凭据处置及固定已知干净版本仍然适用；下文较新的微软指引取代了先前清理后原地降级受影响环境的选项。

**11 月 25 日厂商指引：** 微软称源码仓库为预防起见暂时不可用，须确认能够安全重新启用后才恢复；尚无恢复日期，Agent Framework 也没有停止。恶意代码位于已发布 wheel，而非源码仓库。1.26.0 及更早版本未受影响，但对于从未安装任一恶意版本的用户，建议仍是固定 1.26.0 或所需子包的确切版本，保持固定直至后续指引。这不代表可以使用任意不固定的版本。

若安装过 1.26.1 或 1.26.2，微软要求将主机、容器或 CI 任务按失陷处理，轮换环境可访问的每项凭据，从干净镜像重建，移除受影响环境及缓存／分发副本，并检查 11 月 17 日起的云／CI 审计日志。厂商明确反对原地降级。原有先处理钩子的预防措施仍有助于在保全证据时避免执行载荷，但删除文件不能替代重建。PyPI Security 公告称已与微软审查项目账户并完成处置；这与清理客户已安装环境是两回事，也未披露最初被盗凭据。
