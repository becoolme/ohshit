11 月 6 日报告补充了初始通告未提供的范围：Trigger.dev 称全部客户中 0.66% 受影响，部分环境的 root API key 被取得。这些密钥可完整访问环境设置，包括环境变量。该百分比不是人数、组织数或被盗密钥数量。厂商称已通过 API 日志审查确定范围，未收到影响通知的客户未受影响；投递或账户状态不确定时，应向支持团队核实。

部分环境的近期运行、部署及计划遭列举，涉及运行 ID、部署 ID、计划 ID、任务名、运行幂等键、运行状态、运行标签、部署元数据、部署错误、计划 external ID 及运行元数据。Trigger.dev 未发现其他客户资料、服务、生产数据库或客户仪表盘账户遭访问的证据。这是厂商调查结果，不是对已复制凭据从未遭滥用的独立证明。

Trigger.dev 称已阻断攻击者、缓解攻击路径、轮换内部密钥、审查系统和 API 日志、实施基于风险的账户限制、吊销受影响客户 API 密钥、聘请事件响应专家并通知执法部门，同时发布 scoped key 的 IP 白名单及 OIDC 支持。为保护调查，具体攻击方式仍未披露，没有公开的安全软件版本或完整暴露窗口。自托管和 webhook 签名密钥明确不在本次攻击影响范围内。11 月 1 日的“已解决”状态不能吊销第三方凭据，受影响客户仍需在签发方轮换并部署替代密钥。
