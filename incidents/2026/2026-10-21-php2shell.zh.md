两个漏洞都出在 PHP 自己的引擎里，不是哪个框架或插件的问题。**5.4 以来几乎每个 PHP 版本**都至少受其中一个影响。Apache `mod_php` 风险最高，但 PHP-FPM、`php-cgi`、FrankenPHP 和 LiteSpeed 也都在影响范围内。

原定的披露日期是 10月22日。10月20日晚上，报告团队之一 Calif 意外公开了一段概念验证视频，PHP 随即在 10月21日 14:00 UTC 提前发版。于是这一回，防守方和攻击方难得站在了同一条起跑线上。

**早期报道：** Patchstack 的合作方和 watchTowr 在几小时内就看到了真实的攻击尝试，Cloudflare 也看到了早期尝试。Sophos 没有收到利用报告，截至本文撰写时也没人确认过成功入侵。我们按最坏的可信情况定级：PoC 已公开 + 默认配置即受影响 + 基本覆盖整个 Web = **L5**。

### 常见误解

关掉 `session.upload_progress` **不等于**修复。它只切断了通往 CVE-2026-109619 的已确认路径。内存耗尽那个漏洞 CVE-2026-109618 根本不需要它。

**10月22日更新：** AWS 现已报告广泛在野利用，并在 MadPot 中追溯发现了 10月17日、公开披露前的利用尝试。此前“有争议”的状态已被这份一手报告取代。AWS 没有确认早期尝试能在真实系统上成功。排查至少应回溯至 10月17日；L5 评级不变。

**10月23日更新：** Sophos 在 10月22日更正了 16:18 UTC 关于客户成功入侵的说法。21:21 UTC 的更新称尝试失败，Potassium 载荷被阻止。这修订的是 Sophos 自身观察到的结果，不推翻 AWS 独立的 MadPot 报告。基于已观察到的利用活动，在野状态仍为“已发现”，评级仍为 L5，但不声称客户已成功感染。应将指标与进程、请求及文件证据关联后，再作判断。

**10月22日 ClearPass 更新：** HPE 确认 ClearPass Policy Manager 受这两个 CVE 影响。6.14.0 / 6.11.15 及更早版本完全受影响；6.14.1 / 6.11.16 只能部分缓解，剩余攻击需要已认证的 cluster-admin 权限。**10月23日更正：** HPE 第 2 版公告已为 6.14.1 和 6.11.16 发布完整热补丁。升级基础版本后，还须安装对应的 PHP 热补丁。完成修补前，应通过专用网段和防火墙策略限制 CLI 与 Web 管理访问，并撤下公开访客门户。上方 PHP 运行时版本表和检查器不能判断 ClearPass 设备是否已完成修复。

PHP 还在 10月23日单独披露了依赖罕见配置的上传进度 RCE 风险：[CVE-2026-115560](/zh/incidents/php-session-upload-progress/)。10月21日的运行时补丁未覆盖该问题。

**10月23日 Tenable 更新：** TNS-2026-30 和 TNS-2026-31 涉及相同的两个 PHP CVE。Security Center 6.9.1 及更早版本、Enclave Security 1.9.1 及更早版本受影响。应应用对应产品的 SC-202610.2 补丁：软件包覆盖 Security Center 6.6.0 / 6.7.2 / 6.8.0 / 6.9.1 和 Enclave Security 1.7.0 / 1.8.0 / 1.9.1，将内置 PHP 升级至 8.2.35。单独升级系统 PHP 不能修补产品内置的副本。上方运行时检查器只检查 PHP 本身，不能核实这些设备补丁是否已安装。没有新增已遭利用的客户数量。

独立部署补丁的软件包针对 Oracle Linux 8+ 或 RHEL 8+。Enclave 支持的组合为：Enclave 1.7.0 上的 Security Center 6.7.5、Enclave 1.8.0 上的 Security Center 6.8.0，以及 Enclave 1.9.1 上的 Security Center 6.9.1。按对应的独立部署或 Pod 内安装说明操作。

**10月26日更新：** Adel Karimi 报告在 10月24日，三台运行 PHP 8.4.26、单 worker Apache `mod_php`、内存上限为 128 MiB 的蜜罐上出现 35 次 Shell 启动。这证实的是诱饵系统上的执行，并非 35 家业务受害者。证据支持 CVE-2026-109618，但未证实独立的 CVE-2026-109619 路径；未测量其他环境的利用可靠性。未观察到第二阶段文件下载。修复版本及 L5 评级不变。

另据 Unit 42 10月25日更正，它撤回了 10月23日将欧洲政府机构入侵归因于 PHP2Shell 的说法：无法确认这些 CVE 是初始入侵入口。这不推翻 Karimi 独立的蜜罐证据或 AWS 早期观测。

**10 月 28 日更新：** CISA 已于 10 月 26 日将两个 PHP2Shell CVE 加入 KEV，二者的**联邦修复期限均为 10 月 29 日**，并要求按适用的 CISA 指导开展取证分诊；勒索软件使用情况仍未知。这些条目确认两个 CVE 均遭利用，但没有给出受害者群体，也不能证明 Karimi 观察到的链条使用了两个漏洞。Unit 42 的撤回仍然有效，KEV 收录不会推翻该更正。

**10 月 28 日进一步更新：** Dream 报告在未具名防火墙平台上发现定制 PHP2Shell 到 Fragnesia 攻击链：24 台面向互联网的防火墙及一台内部管理服务器，**未在该调查之外独立核实**。按其描述，恢复的材料证实了凭据提取及目录枚举，但无法确定密码喷洒、后门账号创建或 SAML 密钥提取是否成功。报告未指明厂商，也未证明 AI 编写了漏洞利用。

另据 Palo Alto 的独立通报，面向公网的 PAN-OS 管理界面已遭攻击；这不能确认 Dream 的未具名平台，也不推翻 Unit 42 更早的撤回。PHP 检查器不能判断设备热补丁或内核修复情况。CISA 于 10 月 28 日收录 CVE-2026-46300，联邦期限为 10 月 31 日，并要求取证分诊；勒索软件使用情况仍未知。两个 PHP 漏洞的期限仍为 10 月 29 日。

**10月29日较早更新（已由下文取代）：** 当时 Palo Alto 已发布前五个热补丁；在我们较早的检查中，11.1.7-h12 仍标注预计10月30日发布。按已安装的维护分支选择目标；11.2.10-h16 只修 PHP、h17 同时修 PHP 与 Brotli 的区别，以及管理平面访问限制，仍然适用。
